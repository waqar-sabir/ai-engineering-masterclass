# Phase 2 completion checklist

All items describe future learner work. Materials being Approved does not mark any item complete.

## Knowledge

- [ ] Distinguish training, inference, context, parameters, and activation/cache state.
- [ ] Explain tokenization, special tokens, padding, and explicit truncation policy.
- [ ] Trace neural-network and attention tensor dimensions and causal masking.
- [ ] Distinguish token/sentence representations, pooling, and task suitability.
- [ ] Calculate cosine, dot, and Euclidean behavior including invalid boundaries.
- [ ] Explain encoder compatibility and query/document roles.

## Labs and assignments

- [ ] Tokenization/budget worksheet and independent failure case.
- [ ] Attention/shape worksheet and causal-mask example.
- [ ] Geometry/ranking worksheet and boundary test plan.
- [ ] Snapshot/persistence specification and later real embedding evidence.
- [ ] Model review, frozen split, and coordinated migration plan.
- [ ] Exact-ranking, lexical baseline, and hand-checked metric audit.
- [ ] Design diagram, capacity assumptions, privacy/deletion, and failure analysis.
- [ ] All seven module assessments attempted and reviewed before reading solutions.

## Project and assessment

- [ ] Real vectors generated/stored with a pinned manifest during future implementation.
- [ ] Exact search and artifact invariants tested with recorded evidence.
- [ ] Development and held-out evaluation separated; no-relevant diagnostics included.
- [ ] Honest baseline comparison and measurement methods documented.
- [ ] Final quiz, practical, debugging, system-design, and submission components reviewed.
- [ ] Pass threshold met: 75/100 overall and 20/35 practical, with safe data handling.

## GitHub deliverables

- [ ] Learner implementation and test history submitted when implementation begins.
- [ ] README, schema/manifest example, architecture, evaluation, and failure demo attached.
- [ ] Material changes reviewed on the Phase 2 branch.
- [ ] Explicit owner approval recorded before merge or Phase 3 generation.

## Readiness for Phase 3

Explain why a vector database cannot fix an incompatible encoder or bad relevance labels. Demonstrate an exact-search reference baseline before adding approximate indexing, chunking, document ingestion, and RAG. No Phase 3 detailed content is generated here.
